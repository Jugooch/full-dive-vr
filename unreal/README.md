# Unreal — the experience side

Engine: **Unreal Engine 5.8**, **OpenXR** (Epic native OpenXR, per Meta's current recommendation),
PCVR / Meta Link for development [S45–S48]. See [ADR 0002](../docs/decisions/0002-unreal-openxr.md).

The Unreal project lives in [`PartialDiveVR/`](PartialDiveVR/). It is **not generated by hand**: create it
from the editor (steps below) so the engine writes a valid `.uproject` for your installed version.
Binary assets (`.uasset`, `.umap`) go through **Git LFS** (`.gitattributes` is already configured).

## Create the project (once)

1. `git lfs install` (once per machine).
2. Unreal 5.8 → New Project → **Games → Virtual Reality** template, Blueprint + C++, name
   `PartialDiveVR`, location: this `unreal/` folder.
3. Project Settings → Plugins: enable **OpenXR** (and Meta's OpenXR vendor plugin if using Quest);
   disable legacy OculusVR.
4. Add the LSL plugin for Unreal (labstreaminglayer `plugin-UE`), so the game can push `pdive.game`
   markers on the shared LSL clock.
5. Create the `PartialDiveBridge` plugin (Edit → Plugins → New Plugin → Blank, C++) and implement the
   contract in [`PartialDiveVR/README.md`](PartialDiveVR/README.md).
6. Commit. `.gitignore` already excludes `Binaries/ Intermediate/ Saved/ DerivedDataCache/`.

## Rules

- **Gameplay never reads biosignals.** It reads `IntentFrame`s from the bridge, and nothing else.
- **Unreal never drives actuators.** It emits `HapticEvent`s with the *true* virtual contact; the haptic
  bus applies the experiment condition.
- **No condition logic in Blueprints that the participant can see.** Block params arrive via
  `block/1`; the participant HUD shows only the block code.
- Every scene used in an experiment pushes LSL markers for trial start/end, cues and task events.
